# agent-v10 实验手册

> **7 个实验，每个 1~2 分钟。一个实验只测一个点。**
>
> 实验 2 和实验 6 是本版的主线：**同一件事，启动两次 —— 一次有规划，一次没有。**
> 你亲眼看到的差别，就是「规划」这个知识块的全部。
>
> ⚠️ 手册里所有「你应该看到」都来自**真跑捕获**。
> token 数、耗时、措辞每次都会浮动 —— **看特征，别抠数字**。
> 涉及例子里的具体数字（如 3 步、-1 分），则是当时真实跑出来的结果，我们如实标注。

# 第一组 · 认识规划

## 实验 1：看它先规划、再动手 🆕 ⭐

**🎯 要感受什么**

「执行之前先交一份计划」是什么样子 —— 这是 v10 最直观的一眼。

**⏱ 1 分钟**

**📋 步骤**

```bash
python main.py
```

在 `你 >` 后面输入（或粘贴）：

```
算一下 12 × 34，再把结果记成笔记，标题用 dozen
```

✅ **你应该看到**（节选；数字和计划措辞每次会浮动）：

```
  📋 计划建成（3 步）：
     1. 用 calculator 计算算式 12 × 34，得到精确结果 408。
     2. 用 save_note 把结果存成笔记，标题写「dozen」……
     3. 向用户回复：12 × 34 = 408，并说明已以标题「dozen」保存为笔记。
  🔧 calculator({"expression": "12 * 34"}) → 408
  🔧 save_note({"title": "dozen", "content": "12 × 34 = 408"}) → 已保存到 dozen.md
  🔧 update_plan({"step": 1, "status": "done", …}) → 第 1 步已标记「完成」…｜进度：✅1 ❌0 ☐2
  …
↳ 5 次模型调用（另有规划 1 次） · 7.3s · 7,788 tokens + 规划 897
📋 计划进度：3 步：3 完成
```

❓ 计划步数不是 3？正常 —— 规划器每次拆法可能不同（2~4 步都见过）。
**认准三个特征**：`📋 计划建成`、`update_plan` 的勾选回执、最后一行 `📋 计划进度`。

完成后输入 `/exit` 退出。

**💡 所以呢**

- `📋` 那几行**不是模型在聊天**，是程序把规划结果**打印给你看** ——
  计划被写进了上下文，接下来每一步都带着它（这就是「全局视野」的落地方式）
- `update_plan` 回执里的「✅1 ❌0 ☐2｜下一步：第 2 步」——
  进度是**结构化的账本**，不是随口说说
- 报账行最后那句「+ 规划 897」= 这次规划**多花的** token —— 记住这个伏笔

## 实验 2：关掉规划，同一句话再来一次 ↩️

**🎯 要感受什么**

同一件事、同一个模型，**唯一变量是规划** —— 差别到底值多少。

**⏱ 1 分钟**

**📋 步骤**

```bash
rm -rf notes
LLM_PLANNING_ENABLED=0 python main.py
```

输入**和实验 1 完全相同**的那句话：

```
算一下 12 × 34，再把结果记成笔记，标题用 dozen
```

✅ **你应该看到**（节选）：

```
│ 规划 已关闭（LLM_PLANNING_ENABLED=0）—— 退回走一步看一步     ← 横幅里红字交代
  🔧 calculator({"expression": "12 * 34"}) → 408
  🔧 save_note({"title": "dozen", "content": "12 × 34 = 408"}) → 已保存到 dozen.md
↳ 3 次模型调用 · 3.8s · 2,478 tokens
```

❓ 回答质量差不多？**对** —— 这个任务太短，规划帮不上忙。
看两样东西就够了：**没有 📋、没有 update_plan、token 少一大截**。

**💡 所以呢**

- 对照组的价值：以后你说「规划真好用」，先把这两个数字摆出来 ——
  实验 1：`5 次调用 · 7.3s · 7,788 + 897 tokens`
  实验 2：`3 次调用 · 3.8s · 2,478 tokens`
- 同一件事，规划版**贵 3 倍多**。贵在哪、值不值 —— 实验 6 用尺子说话

## 实验 3：简单问题也被规划（税的滋味）🆕

**🎯 要感受什么**

「不该规划的场合强行规划」长什么样 —— 这一版故意**无条件规划**，
就是要让你亲眼看到它的代价。

**⏱ 1 分钟**

**📋 步骤**

```bash
rm -rf notes
python main.py
```

输入：

```
法国的首都是哪里？
```

✅ **你应该看到**（节选；我们跑过两版，拆 1 步或 2 步都可能）：

```
  📋 计划建成（2 步）：
     1. 确认问题答案：法国的首都是巴黎。
     2. 用中文直接回答用户：法国的首都是巴黎，无需调用其他工具。
  🔧 update_plan({"step": 1, "status": "done", "note": "世界地理常识：……"}) → …
  🔧 update_plan({"step": 2, "status": "done", "note": "……"}) → …
↳ 2 次模型调用（另有规划 1 次） · 5.3s · 2,636 tokens + 规划 863
```

**💡 所以呢**

- 一个**单句问答**，被拆成计划、还打了两轮卡：执行从 1 次调用变成 2 次，
  外加一次规划调用 —— **全部是纯税**
- ⭐ 记住这个场景。实验 6 里评估卷的 `no-tool-paris` 就是它 ——
  那道题的判分标准是「不调用任何工具」，而 `update_plan` 也是工具调用，
  于是**规划把一道满分的题做成了零分**（-1 分的真相）
- 什么时候该规划、什么时候不该 —— 这是本版留给你的思考题，
  也是「分流」欠账的来源

# 第二组 · 破坏它

## 实验 4：把计划弄坏（两种坏法）🆕 ⭐

**🎯 要感受什么**

「计划质量真的决定执行质量吗？」—— 亲手把计划弄坏，看会不会出事。
**结果和直觉不一样，这正是这个实验的价值。**

**⏱ 2 分钟（两个子实验各 1 分钟）**

**📋 步骤 4a：砍掉计划最后一步**

```bash
rm -rf notes
LLM_PLAN_SABOTAGE=drop_last python main.py
```

输入：

```
请依次完成三件事：先算一下 27 × 37 等于多少；再看看现在的时间；最后把这些结果写成一条笔记，标题用 result，内容里要包含计算的结果。
```

✅ **你应该看到**：

```
│ ⚠⚠ 实验模式：LLM_PLAN_SABOTAGE=drop_last —— 计划会被人为写坏    ← 红字，跑不掉
  📋 计划建成（2 步）：                                          ← 原计划 3 步，被砍掉 1 步
  …
📋 计划进度：2 步：2 完成
```

❓ 任务**居然还是完成了**（笔记写出来了）？——对！这就是要你看的：
**模型从任务原文里，把被砍掉的那一步「补」了回来。**

**📋 步骤 4b：颠倒计划顺序**

```bash
LLM_PLAN_SABOTAGE=reverse python main.py
```

输入**同一句话**。

✅ **你应该看到**：计划里步骤顺序是反的（存笔记跑到第一）——
但执行时，工具调用顺序**还是正确的**（先算、再看时间、最后存）。

**💡 所以呢**

- 两次破坏都没砸出坑，答案指向同一句话：**任务原文还在，模型就不完全依赖计划**
- 也就是说，在这种「原文清晰、又不太长」的任务里：
  计划是**位置优势**（把步骤放在眼前），不是**信息优势**（信息原文里都有）
- 💡 反推：计划真正不可替代的场合，是**原文自己都不够用**的时候 ——
  超长任务、步骤依赖看不清、多轮对话后原文漂远了（v2/v3 的领域）
- ⚠️ 别忘了退出实验模式：这两个命令只在启动时生效，正常启动就没有了

## 实验 5：把规划器弄坏（降级）🆕

**🎯 要感受什么**

「增强功能」坏掉时，主流程会不会被连累 —— 工程底线实验。

**⏱ 1 分钟**

**📋 步骤**

```bash
LLM_PLANNER_MODEL=no-such-model python main.py
```

输入：

```
你好，随便聊一句
```

✅ **你应该看到**：

```
  ⚠ 规划失败：规划调用失败：BadRequestError: …400… The supported API model names are
  deepseek-flash, deepseek-v4-pro, but you passed no-such-model. … —— 已退回无规划执行
  （检查 LLM_PLANNER_MODEL / 网络？）
╭───────────────────────── Agent ─────────────────────────╮
│ 你好呀！今天想聊点什么呢？……                              │
╰──────────────────────────────────────────────────────────╯
↳ 1 次模型调用 · 1.4s · 725 tokens
```

**💡 所以呢**

- 规划调用**抛异常**了，但对话**一个字都没受影响** —— 自动降级成「无规划执行」
- 这就是 v3 传下来的降级哲学（压缩失败 → 退回丢弃；向量挂了 → 退回关键词；
  规划失败 → 退回走一步看一步）：**主路径决定你有多好，降级路径决定你能不能用**
- 注意报错里那句「检查 LLM_PLANNER_MODEL / 网络？」——
  故障信息要一路指到**该拧哪个旋钮**，而不是丢一句 400 就完事

# 第三组 · 用尺子量

## 实验 6：评估对照 —— 规划到底值不值 ⭐（本版主线）

**🎯 要感受什么**

「我觉得规划有用」一文不值。**跑两遍卷子，让分数说话。**

**⏱ 约 5 分钟（两次全卷评估）**

**起点** 🆕 清掉旧痕迹，从零开始

**📋 步骤**

第一刀（对照组）：

```bash
rm -rf notes runs
LLM_PLANNING_ENABLED=0 python main.py --eval --tag no-plan
```

第二刀（规划组，直接对比上次）：

```bash
rm -rf notes
python main.py --eval --tag plan --baseline latest
```

✅ **你应该看到**（节选；我们跑的真实结果）：

```
── 第二刀的最后 ─────────────────────────────────────────
通过 11/12（91.7%） · 平均 6.3s/条 · 55 次模型调用 · 79,729 tokens
分类（检查项口径）：工具行为 16/17 · 回答内容 8/8 · 副作用 5/5 · 模型判定 1/1
规划：12/12 条走了规划 · 平均 2.8 步 · 规划开销 10,362 tokens（占总额 13.0%）

对比基线 runs/…-no-plan.json
  通过率    12/12 → 11/12（-1）
  提示词    db60ebd0（没变）
  规划      关（LLM_PLANNING_ENABLED=0） → 开 · 规划器 sha 778b8e51（变了，…）
  ✅ 新通过   无
  ❌ 新失败   no-tool-paris
  ➖ 持平     11 条（11 通过 / 0 失败）
```

❓ 分数和我这里不一样（比如两次都 12/12）？
**正常，而且这本身就是一课**：模型行为有波动，±1 的差别要谨慎解读
（这也是 v9 实验 7 的老教训）。但「**调用次数、token、平均耗时**」的
量级差别（2~3 倍）是稳定出现的 —— 那是规划实打实的账单。

**💡 所以呢**

- 这就是 v9 的尺子 + v10 的第五变量（对比面板里的「规划」行）：
  它能分清「分数变化是规划造成的」还是「波动」—— **不给假因果**
- 这卷的结论（如实）：**规划让分数 -1，让成本 ×3.5** ——
  -1 的机制你可能已经猜到了：`no-tool-paris` 被 `update_plan` 撞死了（实验 3）
- 那长任务呢？看实验 7。

## 实验 7：八步挑战 —— 任务真的变长之后 🆕 ⭐⭐

**🎯 要感受什么**

3~5 步都太短（评估卷里两组全过）。把任务拉到 **8 步**，
看看「任务一长就出事」到底在哪出 —— 这一版最后、最真实的发现。

**⏱ 2 分钟（两轮对话）**

**📋 步骤 7a：有规划，跑八步**

```bash
rm -rf notes
python main.py
```

粘贴这一整段（一次输入）：

```
请按顺序完成八件事：① 计算 11 × 11；② 查询当前时间；③ 计算 22 × 22；④ 再查询一次当前时间；⑤ 计算 33 × 33；⑥ 把三个乘法的结果都写进一条标题是 big 的笔记；⑦ 告诉我 11×11 和 33×33 分别等于多少；⑧ 最后告诉我笔记的文件名。
```

✅ **你会看到两种结局之一**（我们跑了 3 次：1 次顺利、2 次中断）：

**结局 A（顺利）**：`📋 计划建成（8 步）` → 一步步打勾 → `📋 计划进度：8 步：8 完成`。

**结局 B（中断，我们就撞上过两次）**：执行到一半，回答面板里突然出现一段**原始工具语法文本**：

```
│ <｜｜DSML｜｜ calls>
│ <｜｜DSML｜｜ invoke name="save_note">
│ …
```

然后对话就结束了，报账行显示：

```
↳ 9 次模型调用（另有规划 1 次） · 11.6s · 15,627 tokens + 规划 1,031
📋 计划进度：8 步：4 完成 / 4 未标记     ← 任务半途而废了，但你看得出来断在哪
```

**📋 步骤 7b：关掉规划，同一条任务再来一次**

先在输入框输入 `/exit` 退出，然后：

```bash
rm -rf notes
LLM_PLANNING_ENABLED=0 python main.py
```

粘贴同一段八步任务。

✅ 我们跑的真实结果：**无规划 2/2 全部干净完成**（5 次调用、约 5~8k tokens，
八件事全对）。

**💡 所以呢**

- 两个反直觉的事实：
  1. **8 步才开始出事** —— 3~5 步的任务，这套模型走一步看一步也扛得住
  2. **出事的是规划版** —— 多出来的轮次（每步干活 + 打勾）和更长的上下文，
     把模型推到了「工具调用格式失稳」的区间（⚠️ 我们的解释，样本小，
     换模型/换环境可能不同 —— **别当定律**）
- ⭐ 但注意计划账本做了什么：**「8 步：4 完成 / 4 未标记」**！
  循环其实把「任务没做完就当回答结束了」（静默失败），
  是**计划账本让「哪里断的」一眼可查** —— 分数没赢，可观测性赢了
- 这就是下一版（反思）的火种：**任务没完成，必须有人发现它**
