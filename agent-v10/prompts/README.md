# prompts/ —— 提示词也是「配置」，也该文件化

这一版的提示词有**两份角色**，各有各的文件：

| 文件 | 谁在用 | 什么时候改它 |
|---|---|---|
| `system.md` | 执行 Agent（干活的那个） | 想换它的工作规矩时 |
| `planner.md` | 规划器（拆步骤的那个） | 想换它的拆法时 |
| `system-degraded.md` | 实验 6 的「反面教材」 | 别改；它是故意写坏的对照组 |

## system.md

执行 Agent 的系统提示词。**v10 一字没改，和 v9 完全相同** ——
这是有意的：「有规划 vs 无规划」的对比里，它必须是**唯一不动的那部分**，
不然分数变化到底算谁的？

用法（v9 起的老机制）：

```bash
python main.py                                            # 默认用它
LLM_SYSTEM_PROMPT_FILE=prompts/system-degraded.md python main.py   # 换一份
```

## planner.md

⭐ v10 新增。规划器**只做一件事**：把任务拆成步骤清单，调用 `submit_plan` 交卷。

文件里有两个占位符，渲染时会被替换（不是 Python format，是安全的 replace）：

- `{tools}` → 当前可用的工具清单（名字 + 第一句描述；
  被 `LLM_DISABLED_TOOLS` 关掉的不出现）
- `{max_steps}` → 步骤数上限（`LLM_PLAN_MAX_STEPS`，默认 8）

两个设计细节：

1. **只给规划器「工具清单文本」，不给工具 schema** ——
   它该知道「有什么手可用」（拆的步骤才落得了地），
   但它**不该自己也去用**（规划阶段产生副作用就乱了）。
   真要防它的后手还有一层：规划调用时它的工具清单里**只有 submit_plan**。
2. **「太粗 / 太细」两种坏计划写进了提示词** ——
   它们是最常见的两种翻车：「完成用户的任务」（没有信息量）和
   「移动第一个字符」（会被现实推翻）。

改它，然后跑评估 —— 这就是「规划器也能 A/B」：

```bash
python main.py --eval --tag planner-v2 --baseline latest
```

规划提示词的指纹（sha8）会进评估记录，对比面板的「规划」行会显示它变没变。

## system-degraded.md

v9 留下的「坏提示词」：里面写着「不要调用任何工具」。
实验里用它一口气砸掉大半能力，看评估分数掉得对不对。

> 背景小知识（v9 实测）：软性的坏提示词（「尽量别用工具」）压不动模型 ——
> 因为**工具 description 本身也是提示词**，印着「必须调用」。
> 只有这么硬的写法才有效。
