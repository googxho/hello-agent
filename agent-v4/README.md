# hello-agent v4

> 第四个版本。v1 教它「是什么」，v2 教它「别撑爆」，v3 教它「别把记忆扔了」，
> v4 教它**别一关终端就全忘**。

前三版的记忆，保质期单位是**进程**。这一版把它变成**磁盘**。

## 每一版都回答四个问题

这是这个系列的方法论：**不做为了炫技的升级，只解决上一版真实撞到的问题。**

### ① 上一版遇到了什么具体问题？

**v3 的记忆有保质期，但这个保质期的单位是「进程」。**

`messages` 和 `summary_text` 全躺在 Python 变量里。关掉终端 → 变量消失 →
下次启动，你对它来说是个陌生人。

**实测对照**（同一个暗号、同样的两步：第一次启动埋下它，退出；第二次启动问它）：

| | v3 | v4 |
|---|---|---|
| 第二次启动，问暗号 | 「如果你之前是在**别的会话**里设定的暗号，我这边看不到」❌ | **「暗号是『紫色河马』。」** ✅ |

> 注意 v3 那一列的回答 —— 模型自己都意识到了「会话」这个边界的存在，
> 它在向你解释一件你早就知道的事：**上一个进程的东西，它拿不到。**

### ② 这一版引入什么最小概念？

> **把会话（消息 + 摘要）写进磁盘，启动时读回来。**

```
内存里的状态 ──写─→ session.json ──读─→ 内存里的状态
```

概念就这么一句话。**真正的知识量在下面三个坑里** —— 它们才是这一版要学的：

| 坑 | 不处理会怎样 | 这一版的答案 |
|---|---|---|
| **写到一半崩了** | 文件只剩半截 JSON → 整场会话没了 | 原子写：写 `.tmp` → `fsync` → `os.replace()` |
| **文件已经坏了** | 程序一启动就崩，连「从零开始」的机会都没有 | 容错读：**任何异常都不上抛**，降级成明确状态 + 改名备份 |
| **结构以后要变** | 老文件喂给新代码，读出一堆错误字段 | 文件里存 `version`，从第一天就有 |

### ③ 如何验证它真的解决了？

两层验证，都做过：

1. **离线断言**：`--selftest` 里 **69 项**，其中 24 项专门测持久化（存读往返、
   原子写收尾、三种坏文件、结构校验拦截）—— 不需要 API Key，不碰你真实的会话文件
2. **真实重启**：上面那张对照表就是跑出来的 —— 第一次启动埋暗号、退出，
   第二次启动它答得出来

### ④ 下一版的新痛点是什么？

**这一版只解决了「一场会话」的问题。** 剩下两个洞：

| 洞 | 说明 |
|---|---|
| **一个文件 = 一场会话** | 想留十场？得手动复制十个文件。没有「会话列表」，没有「切换」 |
| **它只记得「你说过的话」** | 你问它「我笔记里写了什么」，它一无所知 —— 它不是不记得，是**从来没看过** |

**→ v5 方向**：本地检索（RAG）—— 让它能读你自己的资料（文档 / 笔记 / 代码）。
**→ 中间那步**：会话管理（目录、列表、切换）也可以先做，但那是「更工程」，不是「新概念」。

## 快速开始

沿用你机器上的 `myenv` 虚拟环境（依赖和 v1~v3 完全相同，**零新增依赖**）。

```bash
myenv
cd agent-v4

# 先跑自检 —— 不需要 API Key，不花钱，也不会碰你的会话文件
python main.py --selftest

# 开始对话（会自动恢复上一次的会话）

```

**不需要复制 `.env`。** 配置分两层，各归各位：

| 层 | 文件 | 放什么 | 谁在用 |
|---|---|---|---|
| **共享层** | `<仓库根>/.env` | 密钥、接口地址、模型名 | 所有版本 |
| **版本层** | `agent-v4/.env` | v4 独有的调参 | 可选，不存在也没关系 |

v4 新增这两项，模板见 `agent-v4/.env.example`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `LLM_PERSIST_ENABLED` | 1 | 持久化开关（0 = 退回 v3 的「重启就忘」）|
| `LLM_SESSION_FILE` | `agent-v4/session.json` | 会话存到哪个文件 |

其余项（`LLM_MAX_CONTEXT_TOKENS` / `LLM_KEEP_RECENT` / `LLM_SUMMARY_*` 等）
都是 v2/v3 引入的，原样沿用。

想知道当前到底读到了什么？直接问它：

```bash
python main.py --config
```

## 核心概念：往磁盘上写东西，没那么简单

「存个文件」听起来三行代码就够。但磁盘上的东西，是**你无法控制的环境** ——
这正是这一版真正要学的东西。

### 坑一：写到一半崩了怎么办

最直觉的写法：

```python
# ❌ 危险：写到一半被 kill / 断电 / 磁盘满
with open("session.json", "w") as fh:
    fh.write(json.dumps(payload))
# → 文件只剩半截 JSON → 下次启动解析失败 → 整场会话没了
```

**这一步在开发机上很少出事，在真实环境里天天出事。** 解法是「原子写」：

```python
tmp = path.with_name(path.name + ".tmp")

# 第 1 步：写临时文件
with open(tmp, "w", encoding="utf-8") as fh:
    fh.write(text)
    fh.flush()
    os.fsync(fh.fileno())   # 第 2 步：逼操作系统真的落盘

os.replace(tmp, path)       # 第 3 步：原子替换
```

读你的人（下一个进程）**要么看到完整的旧文件，要么看到完整的新文件** ——
「半截」这个状态从物理上就不存在。

> ⚠️ `fsync` 那一步不能省。少了它，数据可能还在系统缓存里 ——
> 断电之后，你「原子替换」保住的其实是一个空文件。

### 坑二：文件已经坏了，程序不能跟着坏

磁盘上的东西你控制不了：可能是手改坏的、可能是旧版本留下的、
可能是被别的程序截断的。

```python
def load_session(path) -> LoadResult:
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError) as exc:
        backup = _quarantine(path)     # 改名备份，不是删除
        return LoadResult(status="corrupt", note=f"...已备份到 {backup.name}，这次从零开始")
```

读盘的结果被归成四种状态，**每一种都带一句给人看的说明**（铁律 7）：

| 状态 | 什么时候出现 | 程序怎么办 |
|---|---|---|
| `restored` | 文件正常 | 恢复会话 |
| `missing` | 文件不存在（第一次运行） | 从零开始 —— 这是**正常**的，也要说一句 |
| `corrupt` | 解析失败 / 结构不对 | **改名备份** + 从零开始 |
| `future_version` | 文件是更新版本的程序写的 | 不敢乱读，保持原样 + 从零开始 |

**为什么是「改名」而不是「删除」？** 里面可能是你聊了一下午的内容。
程序没有资格替你做主扔掉它 —— 改成 `session.json.corrupt` 放旁边，
你还能自己去看一眼。

### 坑三：结构变了怎么办

文件里存了 `version` 字段：

```json
{ "version": 1, "saved_at": "2026-09-17T23:12:53", "summary": null, "messages": [...] }
```

现在只有一个版本，看起来没用。但**等你需要它的时候再加，老文件里就没有它了** ——
到时候你面对的是「一堆不知道什么格式的文件」，而不是「一个可以判断的字段」。

这是所有持久化格式的通行做法：**版本号从第一天就要有。**

### 还有一个意料之外的坑：两个状态源会打架

`/reset` 命令本来只清内存。加了持久化之后，它就有了新麻烦：

```
/reset  →  内存清空  →  但磁盘上还有  →  下一轮存盘（把空的存进去？）
                                      →  或者中途退出 → 重启后又全想起来了
```

这一版的做法：**`/reset` 同时删掉磁盘文件**，并且如实告诉你删没删到：

```
已清空对话历史（摘要一起清掉）· 磁盘上的会话文件也删掉了
```

> 只要你有「两份状态」（内存 + 磁盘），就一定会遇到它们不一致的时刻。
> 早一点意识到这件事，比早一点写出 bug 好。

📂 已恢复上次会话 · 4 条消息 · 文件保存于 8 秒前

第一次运行、文件坏了、持久化被关掉……**每一种都有话说**（铁律 7）：

```
📂 还没有会话文件（第一次运行就会有）→ /Users/kuki/homework/hello-agent/agent-v4/session.json
📂 会话文件读不了（JSONDecodeError），已把它改名备份到 session.json.corrupt，这次从零开始
📂 持久化已关闭（LLM_PERSIST_ENABLED=0）：这次聊的不会写盘，退出即蒸发
```

### 每轮结束

第一轮会出现一次提示（之后静默，避免刷屏）：

```
💾 已存盘 → session.json（308 B · 1.3 ms） —— 之后每轮都会自动存，不再重复提示；/session 可随时查看
```

### `/session` —— 看磁盘上的真身

```
文件路径  /Users/kuki/homework/hello-agent/agent-v4/session.json
大小      1.0 KB
最后写入  2026-09-17 23:13:02（12 秒前）
内容      4 条消息 · 还没有摘要

（内存里当前有 7 条消息 —— 下一轮结束时会再存一次）
```

> 最后那行括号是刻意留的：**磁盘上的和内存里的不是一回事。**
> 看惯了之后，你就不会再把「我改了内存」误当成「我改了数据」。

## 文件结构

```
agent-v4/
├── main.py         CLI 入口：/summary /session 命令、恢复与存盘、--selftest（69 项）
├── storage.py      ⭐⭐ 本版核心：原子写 + 容错读 + 版本号
├── context.py      ⭐ 上下文管理（v3 的 + export() / restore()）
├── compaction.py   上下文压缩（v3，零改动）
├── agent.py        Agent 主循环（v3，零改动 —— 持久化不该打扰它）
├── llm.py          LLM 调用封装（v3，零改动）
├── tools.py        工具协议 + 3 个工具（v3，零改动）
└── config.py       配置：新增持久化两项
```

依赖仍然是单向的，而且**新加的一层只挂在最边上**：

```
config.py     ← 谁都能读它
   ↑
tools.py / llm.py / compaction.py / storage.py   ← 互不相识
   ↑
context.py    ← 管 messages：剪枝 + 压缩 + 存取
   ↑
agent.py      ← 主循环
   ↑
main.py       ← CLI：负责「什么时候存、什么时候读」
```

**为什么存盘的触发点放在 `main.py`，而不是 `agent.py` 里？**

因为「什么时候存」是个**产品决策**（每轮存？退出存？），
而「怎么存」才是技术问题（原子写）。前者属于 CLI 层，后者属于存储层。
`agent.py` 这一版**一行没改** —— 加一个新能力，不该打扰主循环。

## 常见问题

**Q：我重启之后它确实记得，但 `saved_at` 显示的是上一轮的？**
正常的。每轮结束存一次盘。你最后说的那句话如果还没等到回答就退出，
那一轮就不会被存下来 —— 这是「每轮存」策略的固有边界。

**Q：`session.json` 变大了怎么办？**
它会随对话增长，但**不会无限增长** —— 因为 v3 的压缩在管着：
超过预算的旧内容会被压成摘要，而摘要是很短的。
真觉得太大，用 `/summary` 看看摘要，或直接 `/reset` 重开一场。

**Q：能不能同时保留几场会话？**
能，最土的办法：退出程序后把 `session.json` 复制成别的名字，
想切回去时用环境变量指过去：

```bash
LLM_SESSION_FILE=~/我的存档.json python main.py
```

**Q：文件被我手改坏了，数据还能救吗？**
能。程序不会删它，只会改名成 `session.json.corrupt`。
它是纯文本 JSON，你可以用任何编辑器打开，把要的内容复制出来。

**Q：`--selftest` 会动我的会话文件吗？**
不会。第 ⑤ 组测试全部在系统临时目录（`/tmp` 之类）里跑，
跑完就删，**碰都不碰** `agent-v4/session.json`。

## 动手练习

1. **读一遍 `session.json`** —— 对照 `/summary` 的输出，看看「磁盘上的记录」
   和「它脑子里的记忆」差在哪
2. **把 `saved_at` 改成 3000 年**（手改文件）—— 重启，看「文件保存于」那行怎么显示。
   这就是「数据不可信」的第一课
3. **给会话文件加一个「标题」字段** —— 让它在保存时自动从摘要或第一句话里取，
   `/session` 里显示出来。这是「会话列表」的雏形
4. **实现「退出时才存」** —— 加一个 `LLM_AUTOSAVE=off` 开关，
   对比两种策略的代价。然后回答：为什么推荐每轮存？
5. **做一次真正的崩溃测试** —— 在 `save_session()` 里加一个 `os._exit(1)`，
   放在写 `.tmp` 之后、`os.replace()` 之前，看看你的会话文件有没有坏
