> 然后按名次把两边的结果合起来。

## 每一版都回答四个问题

### ① 上一版遇到了什么具体问题？

v6 的实验 6 / 7 摆出了两个同样真实、方向相反的事实（干净对照，固定查询词）：

| 查询 | 关键词（v5）| 向量（v6）|
|---|---|---|
| 怎么让程序跑得更快 | **0 命中 ✗** | **1 命中（0.651）** ✓ |
| ERR_5002 | **1 段稳稳命中 ✓** | 0.556 —— 门槛从 0.5 抬到 0.6 就死 ✗ |
| 番茄需要浇多少水 | 0 命中 | 0 命中（0.362 < 门槛）✓ |

**两把尺子，盲区几乎不重叠**：一个漏同义、一个漏精确；一个保守、一个冒进。
v6 的 README 把「混合检索」列为下一版 —— 这一版就是来还这笔账的。

### ② 这一版引入什么最小概念？

> **两个都跑，然后融合排名 —— RRF（倒数排名融合）。**

```
查询 ──┬─→ 关键词检索 ─→ 名单 A ─┐
       └─→ 向量检索   ─→ 名单 B ─┴─→ RRF ─→ 前 N 段 ─→ 塞进上下文
```

RRF 的核心顿悟只有一句话：**分数不可比，但名次是通用语。**

$$\text{融合分}(d) = \sum \frac{1}{k + \text{名次}(d)}$$

被一边提名拿一份分，被两边都提名拿两份 —— 于是**共识是真金白银**：

```
关键词名单：[B#1, C#2, D#3]        向量名单：[A#1, E#2, B#3, C#4]

k=60 融合后：  B(0.0323) > C(0.0318) > A(0.0164) > E > D
                └─ 两边都提名 ─┘        └ 向量侧第一名，但只有单边提名
```

看 A 和 C 的对比：**A 在向量那边是第一名，却输给名次平平的 C** ——
因为 C 被两条独立的路同时看中。这就是这一版的全部魔法。

### ③ 如何验证它真的解决了？

1. **离线**：`--selftest` 共 **127 项**，其中 26 项专测融合这条线
   （纯函数手算核对、共识加成、去重、k 翻转、depth 截断、单边救场、降级）——
   不联网、不花钱
2. **干净对照**：三种模式并排跑同一批查询（下表），固定查询词、绕开模型
3. **双票的价钱**：同一查询、只动门槛 0.5→0.6，融合分腰斩 `0.0328 → 0.0164`
   （两路都在帮它 vs 只剩一票）—— 见实验 4

### ④ 下一版的新痛点是什么？

这一版留下的坑：

| 坑 | 说明 |
|---|---|
| **旋钮四件套** | 门槛、k、depth、top_k —— 好结果依赖手工实验，没有系统的评估办法（这是知识块 07）|
| **人肉看日志** | 「改了 k 到底变好还是变坏」——目前只能靠实验手册这种一叠人肉记录 |
| **成本** | 每次检索多跑一遍：关键词免费，向量要算查询（约 5 tokens/次，块向量走缓存）|
| **它还是不会自己去查** | 同 v6：查不查由模型决定（提示词 + 低温在管着）|

**→ 下一版方向**：**结构化输出**（知识块 06）。

为什么不是先做「评估」（07）？因为评估的第一步就会卡住：**判定要程序化** ——
「期望命中」「好/坏」现在全是给人看的自由文本，连实验都是一叠人肉记录。
要让程序自动消费、自动判定，先得让**模型的输出**变成程序能可靠解析的结构
（JSON Schema、校验、失败重试）—— 这正是 06；做完它，07 评估才是顺水推舟。

## 核心概念：三个想清楚了的决定

### 决定一：每一路按自己的老标准发言

关键词侧「有词命中」才算、向量侧过了 `LLM_MIN_SIMILARITY` 才算 ——
各自的命中规则**一个没改**，RRF 只合并命中项。

于是 v5 的「宁缺毋滥」和 v6 的门槛行为原样保留；0 命中的查询不会被硬塞 ——
**RRF 没有无中生有的本事**（实验 3 的最后一行为证）。

### 决定二：合并按「内容」去重

同一段被两路同时提名 → 并成一条、分数相加。身份用 (文件, 行号, 内容) ——
内容才是「同一段」的判据，文件名不是。

### 决定三：每条结果都带两边的名次

这就是为什么日志长这样（真实输出，见实验 2）：

```
🔍 检索 ERR_5002 故障代码 （混合） → 1 段命中（关键词提名 1 段 + 向量提名 1 段 → RRF k=60 · 扫描 2 块 · 2461.2 ms）
      model.md:3（设备） · 关键词#1（打分 1.11） + 向量#1（余弦 0.662） → 融合 0.0328
```

结果不对劲时，这一行直接告诉你**是关键词的锅还是向量的锅**（铁律 7）。

## 三种模式的日志，怎么读

| 你看到 | 它在说 |
|---|---|
| `（混合）→ 3 段命中（关键词提名 2 段 + 向量提名 1 段 → RRF k=60）` | 两路各提名了几段 —— 谁在帮忙、谁在旁观，一目了然 |
| `关键词#1（打分 0.28） + 向量#1（余弦 0.556） → 融合 0.0328` | 这条被两边都提名（双票）；两种原始分**不可相加**，别去加 |
| `（混合）→ 0 段命中（关键词 0 词命中；向量最高 0.444 < 门槛 0.5）` | 两路都说了话、都没票 —— 不是某一侧哑火 |
| `（关键词）→ …` + `⚠ BadRequestError…` | 向量服务挂了，自动降级到 v5 的找法（不偷偷降级）|

`/knowledge` 也会说清楚现在的模式：

```
2 个文件 · 检索模式：hybrid（关键词 + BAAI/bge-m3 → RRF k=60，每边取前 10 段）
```

```bash
python main.py --selftest
```

**127 项断言**，八组。第 ⑧ 组专测融合（全部离线）：

| 场景 | 关键断言 |
|---|---|
| **H1** 融合数学 | ⭐ 手算核对：`B=1/61+1/63`；共识的 C 压过单边冠军 A |
| **H2** k 旋钮 | ⭐ k=0 时 A 反超 C（单边霸权抬头）|
| **H3** depth 截断 | 名单之外 = 没名次，好结果进不来 |
| **H4** 换说法 | ⭐ 关键词 0 命中 → 向量一路把结果送进榜单 |
| **H5** 精确编号 | ⭐ 向量弃权 → 关键词一路稳稳兜住 |
| **H6** 双票 vs 单票 | ⭐ 关键词#2+向量#1 压过关键词#1 |
| **H7** 门槛联动 | 余弦 0.6：门槛 0.5 提名、0.7 弃权；融合分正好腰斩 |
| **H8** 两路都空 | 0 命中 —— RRF 不会无中生有 |

> 全部离线：向量用**脚本替身**（按规则发向量，零向量 = 弃权），
> 不联网、不花钱、结果完全可复现。

**真实对照**（需要 Key）：见「四个问题①」的表格和实验 3 ——
同一个脚本里三种模式并排，能直接看到「混合 = 两边各自救场的并集」。

## 常见问题

**Q：还想看 v5 / v6 的老找法怎么办？**
切模式就行，一秒回去：

```bash
LLM_RETRIEVAL_MODE=keyword  python main.py   # v5：只比字面
LLM_RETRIEVAL_MODE=semantic python main.py   # v6：只比意思
```

**Q：k 该设多少？depth 该设几？**
默认 k=60 是文献里的经验值（v7 没做调优）；depth=10 对几百块的资料库够用。
**这两个值和门槛一样，没有普适真理** —— 调参需要评估集，那是知识块 07。
现在想感受它们的作用，跑实验 4 / 5。

**Q：混合模式是不是「1+1=2」的效果？**
不是。它是「各救各的场」：关键词保精确、向量保语义，**共识只是加分项**。
两边都空的时候，结果还是空（实验 3 最后一行、selftest H8）。

**Q：成本怎么算？**
每一次检索 = 1 次查询向量（约 5 tokens，不缓存）+ 免费的关键词扫描。
块向量第一次算完进缓存，之后免费。混合带来的边际成本 ≈ **一次查询向量**。

**Q：改了资料，缓存和融合会怎样？**
块向量只重算变过的那几块（v6 的机制没动）；融合每次都现算 ——
它是纯计算，不花钱、不缓存。

**Q：`⚠ BadRequestError…` 又出现了？**
还是 v6 那个故事：向量服务调不通（断网 / 配额 / 模型名写错）→
自动退回关键词检索，检索日志里的 tag 从 `（混合）` 变 `（关键词）`，
并用 `⚠` 说明原因。**功能没丢，「同义词又搜不到了」** —— 这就是降级的代价。

## 动手练习

1. **给你的资料做一张三模式对照表** —— 抄实验 3 的脚本，换上你的问题和笔记，
   看看你的资料上「哪一路在救场」更多
2. **扫描 k 和 depth** —— 把实验 5 的构造名单换几组，找一组「k 大时共识赢、
   k 小时单边赢」的临界值（体会「k 的含金量」到底怎么变）
3. **改一条路线试试** —— 在 `rrf_fuse` 里把 `1/(k+rank)` 换成 `1/rank²`，
   跑一遍 selftest，看哪些断言挂了、为什么
4. **给融合加个「证据门槛」** —— 比如「至少被一边排进前 3 才进最终名单」，
   想想它和 `depth` 有什么区别
5. **思考题**：如果向量侧不设门槛、让它的 top 10 全员进融合，会怎样？
   （提示：查「番茄需要浇多少水」—— 融合后会不会突然「有结果」了？）
