# hello-agent v8

> 第七版让它两条路都会走，这一版让机器终于**读得懂它的话** ——
> 它必须通过 `submit_result`「交卷」，交出来的是一个能被程序校验、消费的 JSON。

v7 收尾时留下的原话：「**「改了参数到底变好还是变坏」没法回答：目前全靠人肉看日志**」——
因为它的回答是一段散文：想知道它引用了哪个文件？靠猜。想批量判定对错？没法判。

## 每一版都回答四个问题

### ① 上一版遇到了什么具体问题？

v7 的四个问题④里写得很直白：

- **旋钮四件套**（门槛 / k / depth / top_k）：好结果依赖手工实验，没有系统的评估办法
- **人肉看日志**：「改了 k 到底变好还是变坏」——只能靠实验手册这种一叠人肉记录

而做「评估」的第一步就卡住：**判定要程序化，可模型的话进不了程序。**

```
模型输出（自由文本）：             程序需要（结构化）：
「你的笔记里说了三个方向，         {"answer": "…",
  加缓存、减少重复计算……            "found": true,
  出处是 perf.md」                   "sources": ["perf.md"],
                                     "confidence": 0.9}
    → 想知道出处？写正则去文中猜      → 直接读字段，能校验、能统计
```

### ② 这一版引入什么最小概念？

> **给模型的输出也定一份 schema —— 用你早就在用的机制：工具调用。**

从 v1 起，工具的**参数**就是 JSON Schema。这一版把「最终回答」也变成
一组工具参数：模型必须调用 `submit_result(...)` 把结果**交上来**：

```json
{
  "answer":     "给用户看的答案",
  "found":      true,            ← 有没有笔记依据（false 时 sources 必须为空）
  "sources":    ["perf.md"],     ← 引用了哪些文件（只能引用本次检索真见过的）
  "confidence": 0.9              ← 把握几成（模型自报）
}
```

**实现路线的选择**（外面还有两条路，见下）——这里选「工具即 schema」：
对任何支持 tool calling 的模型都通用，DeepSeek 也能直接吃，而且**不引入新机制**。

> ⚠️ **schema 约束 ≠ 保证。** 接口层能保证「长得像 JSON」，
> 保证不了「说得对」。所以还要第二层：**校验**。
>
> | 校验层 | 例子 | 谁能抓 |
> |---|---|---|
> | 类型 | 字段全不全、confidence 是不是数字 | 校验器 |
> | 语义 | answer 非空、found 和 sources 自洽 | 校验器 |
> | ⭐ **交叉核对** | sources 引用了**本次没检索过的文件**（编造出处！）| 轨迹（search_notes 的账本）|
>
> 校验不过 → 把「哪里错了」**回灌**给模型 → 再交一次 —— 这就是**失败重试**。
> 试满上限（默认 3 次）就**放弃**：`ok=false`、退出码 2，绝不假装成功。

### ③ 如何验证它真的解决了？

1. **离线**：`--selftest` 共 **152 项**，其中 26 项专测结构化这条线 ——
   校验器逐条喂坏数据、**剧本客户端**重放（坏→好、坏到底）、轨迹、开关，全都不花钱
2. **真实运行**：`--ask` 人读模式 + `--json` 模式（stdout 纯净、退出码 0）
3. **批量表格**（实验 3，真实输出）：三个问题一次跑完，程序直接读 JSON 汇总 ——
   第三个问题如实回答 `found=False`、`sources=[]`（不知道的没编）
4. **失败面**：模型名写错 → `ok=false` 信封 + 退出码 2（实验 6）

### ④ 下一版的新痛点是什么？

这一版解决了「读得懂」，但还没解决「**不知道好坏**」：

| 坑 | 说明 |
|---|---|
| **没有评估集** | 只有零散的手工问题；「该找到什么、找到没有」没有一份可重复的期望 |
| **没有 trace 汇总** | 每次运行的关键事实（调用几次、命中什么、重试几次）散在日志里 |
| **confidence 是自报的** | 模型说自己 0.95 —— 它能信几成？需要拿评估数据校准 |
| **校验只到「形式 + 可核对」** | 它拦不住「格式全对、内容是错的」——那需要**评估**来打分 |

**→ 下一版方向**：**评估与可观测**（知识块 07）。

v8 已经把它的地基铺好了：机器可读的输出（`--ask --json`）、程序的自动消费
（实验 3 的批量表格）、甚至「机器记的 meta」（attempts / failures / sources_seen）。
下一步就是给它加三样东西：**eval 集**（问题 + 期望）、**trace**（每次跑留下什么）、
**指标**（hit@k、引用正确率……）—— 然后才谈得上「改了旋钮，到底变好了没有」。

## 核心概念：让模型「交卷」

### 三条实现路线（为什么选第三条）

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| 原生 Structured Outputs | 接口层强制 JSON Schema（OpenAI 系） | 服务端保证形状 | 供应商绑定；不是每家都有 |
| JSON 模式 | `response_format={"type":"json_object"}` | 保证「像 JSON」 | 不管 schema；仍要自己校验 |
| ⭐ **工具即 schema**（本项目）| 把输出做成一个工具的**参数** | 任何支持 tool calling 的模型都能用；复用 v1 的机制 | 依赖模型愿意调用工具 |

（外面谁在用、各自怎么做 —— 见 [ECOSYSTEM.md](../ECOSYSTEM.md) 的 06 一节。）

### 失败重试「长」在哪？——不需要新机制

`submit_result` 校验失败时**抛 ValueError**；agent 循环会把异常包成
「工具错误」回灌给模型（v1 就有的行为）—— 模型看到错在哪，改完再交一次：

```
🔧 调用 submit_result(...) 
✗ 错误：ValueError: 第 1 次提交不合规（还剩 2 次机会）：sources 里的 ['幽灵文件.md']
  不是本次检索见过的文件（见过的只有：perf.md） —— 出处必须是真实检索结果，不能编造。
  请修正后重新调用 submit_result。
🔧 调用 submit_result(...)     ← 模型改好了
← 已收到结构化结果，校验通过。本次任务结束。
```

试满上限后改为抛 `StructuredGiveUp` —— 它**刻意穿透** agent 循环
（不是「可回灌的工具错误」，而是「这次运行已判死刑」），交给运行器收尸。

### 三种结局，三种姿态

| 结局 | 输出 | 退出码 |
|---|---|---|
| 拿到合规结果 | `ok=true` + result | 0 |
| 放弃 / 报错 | `ok=false` + `meta.error` + `meta.failures` | 2 |
| 模型压根没交卷 | `ok=false` + 说明「它可能直接输出了文字」 | 2 |

### `--json` 的输出契约

**stdout 只允许出现一个 JSON 文档**；横幅、工具日志、检索日志全部去 stderr。
这是所有 CLI 工具的通用契约：**日志是给人看的，JSON 是给程序吃的。**

```
$ python main.py --ask "…" --json > out.json 2> log.txt
$ echo $?
0
$ cat out.json | python -m json.tool --no-ensure-ascii | head
{
    "question": "笔记里 ERR_5002 这个故障代码是什么情况？",
    "ok": true,
    "result": { "answer": "…", "found": true, "sources": ["model.md"], "confidence": 0.95 },
    "meta": { "attempts": 1, "failures": [], "sources_seen": ["model.md"], "error": null, … }
}
```

⚠️ `result` 是**模型交的**（已过校验），`meta` 是**程序记的** ——
两层刻意分开：将来做评估时，模型说的和机器看到的不混在一起。

## 什么时候**不该**用结构化

**交互对话没变** —— 还是自由文本回答。这不是偷懒，是原则：

- 给人看的聊天，JSON 是枷锁（「今天心情怎么样」没法填进四个字段）
- `submit_result` 只在 `--ask` 模式出现在模型的工具清单里（selftest J6 盯着这条）

**该用**：输出要被程序消费时（批量问答、评估、流水线对接）。
**不该用**：输出只给人看时。判断标准就一句：**下一站是人眼，还是代码？**

## 文件结构

```
agent-v8/
├── structured.py   ⭐⭐ 本版核心：校验器（纯函数）+ 提交状态 + 放弃信号 + 模式提示词
├── tools.py        工具五 submit_result + 轨迹 SEEN_SOURCES + ToolParameter 支持数组
├── agent.py        ⭐ v1 以来第一次动主循环：放行放弃信号、交卷即收工、长参数显示截断
├── main.py         --ask / --schema、⑨ 组自检；横幅改用「真实工具清单」当唯一来源
├── config.py       新增 LLM_STRUCTURED_MAX_ATTEMPTS
├── retrieval.py / embedding.py / context.py / storage.py / compaction.py / llm.py
│                   （v7，零改动 —— 换「输出方式」不用碰检索、记忆、压缩任何一层）
└── .env.example    v8 新增一节
```

**为什么 `structured.py` 和工具分开？** 工具（`tools.py`）负责「和模型打交道」
（schema、提交入口）；`structured.py` 负责「和正确性打交道」（规则、状态、放弃）。
**校验器是纯函数**（数据进、问题列表出）—— 所以 selftest 能一行行喂坏数据，
不用起模型、不用联网。

## 常见问题

**Q：它提交失败了怎么办？**
看 `meta.failures`（或人读模式的 `↻` 行）——错误里会写清「哪里错、怎么改」。
如果模型总是改不对：调大 `LLM_STRUCTURED_MAX_ATTEMPTS` 给它多点机会，
或者换一个更听话的模型；实在不行就接受 `ok=false` —— **这比拿到脏数据好**。

**Q：想让它输出别的字段（比如 `next_step`）？**
要改两处、必须对齐：`tools.py` 的 `SUBMIT_RESULT_DEF`（给模型看的）
和 `structured.py` 的 `validate_submission`（程序验的）。
这两处是哪一版都绕不开的「契约的两面」——改完跑一遍 `--selftest`，J 组会告诉你漏没漏。

**Q：为什么不直接用模型原生的 Structured Outputs？**
三条路线各有取舍（见上表）。这里选工具即 schema 的三条理由：
① 通用性 —— 换任何支持 tool calling 的模型都不断；
② 可测性 —— 校验/重试/放弃全都能离线测，不依赖供应商行为；
③ 教学性 —— 用的还是 v1 那套机制，没有「魔法」。

**Q：`--ask` 会读写会话文件吗？**
不会。它是**单发**模式：不读 session.json、也不写 —— 每个问题互相独立。
这是刻意设计：批量跑评估时，上一个问题绝不能污染下一个。
（交互对话才有「记忆」。）

**Q：`confidence` 能信吗？**
当成「模型的自我感觉」：用它排序、筛查可以，**当真理不行**。
它值多少，得拿评估数据校准 —— 那是 07 的事。

**Q：它干脆不交卷、直接输出一段文字呢？**
会被运行器识破：`ok=false` + `meta.error` 里写明「它可能直接输出了文字」，
退出码 2。提示词里写了「必须提交」，加上工具的强引导，实测没遇到过；
但**就算发生也有一层网兜着** —— 这就是「放弃也是结果」的意义。

## 动手练习

1. **加一个字段**：给 schema 加 `"next_step"`（string：建议的下一步），
   两处对齐后跑 `--ask`，看模型怎么填
2. **把校验器改严**：比如「answer 少于 20 字算不合规」——观察重试、
   以及 `failures` 里记了什么
3. **看一次放弃**：`LLM_STRUCTURED_MAX_ATTEMPTS=1` 跑几次 `--ask`，
   碰上一次「第一次就不合规」你就能看到完整的失败路径
4. **写一个批量小工具**：抄实验 3 的脚本，把 N 个问题跑成一张 CSV
   （问题 / found / sources / attempts）—— 这就是 07 评估的种子
5. **思考题**：为什么 sources 的校验要跟「本次检索轨迹」对，
   而不是跟「文件系统里有没有这个文件」对？
   （提示：一句「引用了没检索过的文件」的答案，问题出在哪？）
