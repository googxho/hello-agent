# hello_agents_test

> **给 `hello_agents` 框架做「体检 + 演示」的独立小工程。**
> 不需要 API Key 就能跑完一整套回归自检；想看真实效果时再加一个参数。

---

## 为什么要单独建这个文件夹？

1. **不碰源码**：`hello_agents/` 是框架本体（也正在被逐文件加注释），这个 demo 一行都不改它。
2. **自检全部离线**：用假模型客户端顶替真模型 —— 不花钱、不受网络影响、**回复可预测**
   （真实模型每次回答都不同，没法断言「第 3 轮该返回什么」）。
3. **把踩过的坑变成断言**：下面那 6 条已知缺陷，都是这几个小时里真跑出来的。
   它们现在是**黄色告警**而不是"口头提醒" —— 修好之后会自动变绿，改坏了会变红。


## 文件结构

| 文件 | 行数级别 | 作用 |
|---|---|---|

## 自检覆盖什么

### 第 1 组 · core 三件套
- `Message`：位置参数能用的**原因**、`Literal` 在 Pydantic 字段上**运行时真的校验**、
  `to_dict()` 为什么只剩两个键
- `Config`：字段默认值、`@classmethod` 的**描述符机制**、`self.dict()` 的废弃警告
- `Agent`：抽象类为什么不能实例化、**账本机制**（`__abstractmethods__`）、
  `get_history()` 的防御性拷贝、历史为什么是每实例独立的

### 第 2 组 · 工具系统
- `Tool` 是抽象类（两个方法都必须实现）
- `@tool_action` **展开机制**：一个父工具 → N 个可独立调用的子工具
- `get_tools_description()` 就是**喂给模型的提示词**
- 两种注册方式（`register_tool` vs `register_function`）的**行为差异**
- 内置 `calculator` 的当前状态

### 第 3 组 · 六个 Agent 范式（行为级）
- 继承契约：5 个直接继承 `Agent`，`ToolAwareSimpleAgent` 是唯一的二级继承
- `SimpleAgent`：无工具 1 次调用；**有工具时循环 2 次，且工具结果以 `user` 消息回灌**
- `ReActAgent`：`Finish[...]` 收尾、失败时 `Observation` 回灌、跑满步数的熔断
- `ReflectionAgent`：「无需改进」提前停止 vs 跑满轮数（用**调用次数**断言）
- `PlanAndSolveAgent`：1 次规划 + N 步执行；计划格式不匹配时静默退化成"任务终止"
- `ToolAwareSimpleAgent`：同一段文本，父类正则**截断**、子类状态机**完整**
- **流式的真与假**：同名接口 `stream_run`，一个逐片、一个一次性

## 关键手法：为什么能用假模型？

因为 `Agent` 只在**运行时**读 `self.llm` 的几个属性和方法，而 Python **不做类型检查**
（鸭子类型）—— 只要对象"长得像" `HelloAgentsLLM`，就能顶替它。

```python
llm = FakeLLM(replies=["第一轮回复", "最终答案"])   # 按脚本吐
agent = SimpleAgent(name="x", llm=llm)            # 真 Agent + 假模型
agent.run("问题")
print(llm.call_count)        # ← 精确知道模型被调用了几次
print(llm.flat_text())       # ← 精确检查工具结果有没有被回灌
```

这条在 `core/agent.py` 里被验证过：`llm: HelloAgentsLLM` 只是注解，不参与运行。

## 已知缺陷清单（体检报告）

跑 `--selftest` 会看到这些 **⚠ 黄色告警**（不算失败，但会一直提醒）：

| # | 位置 | 缺陷 | 影响 |
|---|---|---|---|
| 1 | `core/config.py` | `to_dict()` 用 Pydantic v1 的 `self.dict()` | 每次都发废弃警告，v3 会直接删掉 |
| 2 | `tools/registry.py` | `get_tools_description()` **只输出「工具名: 描述」，不含参数名** | 模型不知道参数名只能猜 → 猜错就 `unexpected keyword argument`。**实测：`--live` 第一次跑就因此失败** |
| 3 | `tools/base.py` | `AutoGeneratedTool.run` 是 `self.method(**parameters)`，而注册表固定传 `{"input": ...}` | `@tool_action` 方法的形参不叫 `input` 时，纯文本调用必崩 |
| 4 | `agents/simple_agent.py` | `_execute_tool_call` 只查 `Tool` 对象，不查函数式工具 | 模型被告知有个工具，调用却说"未找到" |
| 5 | `tools/builtin/calculator.py` | `isinstance(node, ast.Num)` —— `ast.Num` 在 Python 3.12 已移除 | **计算器在 3.12+ 上完全不可用**，任何算式都失败 |
| 6 | `agents/function_call_agent.py` | `stream_run` 是 `run()` 跑完再 `yield` 一次 | 名不副实：`hasattr(obj,'stream_run')` 为真 ≠ 真流式 |

> 缺陷 2、3、4 是同一条链上的三个环：**工具说明不给参数名 → 模型猜 key → 
> 猜错了还会撞上"形参必须叫 input"的硬约定**。想真正修好，得三处一起动。

## 注意事项

- **Python 版本**：本机 myenv 是 3.14。计算器缺陷（第 5 条）从 3.12 起就存在。
- **代理变量**：本机的 `all_proxy=socks5://...` 会让 httpx 报
  `Using SOCKS proxy, but the 'socksio' package is not installed`；
  `no_proxy` 里的 `[::1]` 又会触发 `InvalidURL: Invalid port: ':1]'`。
  这两个已在 `main.py` 的 `sanitize_proxy_env()` 里按需清理，并且**删了哪几个会打印出来**。
  如果你的网络必须走代理，请改用 `pip install "httpx[socks]"`，别用那个函数。
- **`.env` 的键名不一致**：`core/llm.py` 读 `LLM_MODEL_ID`，而仓库 `.env` 里写的是 `LLM_MODEL`
  —— 结果配置**不生效**。跑 `main.py --config` 能直接看到
  「.env 里配的是 `deepseek-flash`，实际用的是 `deepseek-chat`」。
