# agent-v3 实验手册

> **「它记住了」这件事，光看代码是感受不到的。**
>
> 这一版的实验分三组，顺序是有讲究的：
>
> 1. 先**感受新能力**（它记得住了）
> 2. 再**亲手把它拆掉**（这样你才知道真的是它在起作用，而不是运气）
> 3. 最后**感受代价**（天下没有免费的记忆）

---

## 怎么用

- 开两个窗口：一个跑 Agent，一个看这份文档
- 每个实验四段：🎯 要感受什么 → ⌨️ 敲什么 → 👀 看什么 → 💡 所以呢
- **标记 ⭐ 的是必做**；⭐ 越多冲击力越强
- 需要改代码的实验（第 4 个），文末有「一键复原」办法
- 全部做完大约 45 分钟

### 速查表

| # | 实验 | 感受什么 | 组 |
|---|---|---|---|
| 1 | 它这次记得了 ⭐⭐⭐ | 压缩带来的**记忆存续** | 第一组 |
| 2 | 扒开它的记忆看看 ⭐⭐ | 摘要长什么样、漏了什么 | 第一组 |
| 3 | 关掉压缩 ⭐⭐ | 破坏性：能力真的是它带来的吗 | 第二组 |
| 4 | 把摘要模板改坏 ⭐⭐ | 压缩质量取决于提示词 | 第二组 |
| 5 | 让压缩失败 ⭐ | 工程底线：失败也不崩 | 第二组 |
| 6 | 把阈值调到天上去 ⭐⭐ | v3 退回 v2，而且日志会招供 | 第二组 |
| 7 | 压缩的账 ⭐⭐⭐ | 花 789 省 150，图什么 | 第三组 |
| 8 | 压了又压 ⭐⭐⭐ | 误差累积：记忆的漂移 | 第三组 |
| 9 | 摘要的「分辨率」⭐ | 压缩比 vs 保真度 | 第三组 |

# 第一组 · 它现在记得住了

## 实验 1：同一个暗号，昨天它忘了，今天它记得 ⭐⭐⭐

**🎯 要感受什么**

v2 的实验 7 里，你亲眼看着它忘掉「紫色河马」。**现在用完全相同的剧本再演一遍。**

这是整个 v3 存在的理由，也是这份手册最值得做的一个实验。

**⌨️ 敲什么**

把预算压小，启动：

```bash
LLM_MAX_CONTEXT_TOKENS=500 LLM_KEEP_RECENT=4 python main.py
```

然后**逐句**输入下面这 9 句（一句一句来，别一次贴完）：

```
请记住这个暗号：紫色河马。只回复「好的」两个字，不要调用工具。
帮我算 1234 * 5678
北京是哪个国家的首都
帮我算 999 * 888
水的沸点是多少度
帮我算 12345 + 67890
今天几号？
再见用日语怎么说
我刚才让你记的暗号是什么？
```

**👀 看什么**

盯着终端，注意这条时间线：

| 阶段 | 你会看到 |
|---|---|
| 前几轮 | `上下文 约 183 → 448 / 500 tokens`，一路往上涨 |
| 某一轮之后 | `🗜 正在压缩旧对话…（这一步要额外调一次模型）` |
| 接着 | `🗜 第 1 次压缩：5 轮旧对话（14 条消息） → 摘要 161 tokens，压缩比 52%` |
| 同时 | `上下文 501 → 409 tokens` —— **掉下来了** |
| 最后一句 | 它答：**「你让我记的暗号是「紫色河马」」** |

✅ **它记得。** 而在 v2 里，这一幕的结局是「答不上来，而且没有任何报错」。

> ⚠️ 如果你的对话比这个短，可能看到的是 `✂ 丢弃 1 轮旧对话` ——
> 别慌，**紧跟的下一行会告诉你原因**：
> `⏭ 没有走压缩：可压内容只有 X tokens，低于阈值 200`。
> 这是设计好的行为（详见实验 6），不是压缩坏了。

> ⚠️ 如果跑了 8 轮还没看到 `🗜`，再加两轮无关对话。
> 触发时机取决于你的预算和对话长度 —— 差一点点就是压不了。

**💡 所以呢**

这是第一次，你**同时**拥有两样东西：

- 上下文没有爆（v2 的功劳：token 预算 + 剪枝）
- 信息没有丢（v3 的功劳：压缩）

而中间只改了一处：`del messages[start:end]` 之前，先问一次模型
「这段你记得住吗」。

## 实验 2：扒开它的记忆看看 ⭐⭐

**🎯 要感受什么**

摘要不是黑盒。**你能直接读它。** 而且读懂它漏了什么，比读懂它保住了什么更有用。

**⌨️ 敲什么**

接着实验 1 的对话，随时敲：

```
/summary
```

再看一眼状态：

```
/context
```

**👀 看什么**

`/summary` 会把摘要全文摊开给你看，大概长这样：

```
【对话摘要】
目标：用户要求记住暗号并完成了若干计算与常识问答。
关键信息：用户的暗号是「紫色河马」。
已确认的事实：1234×5678=7006742；999×888=887112；12345+67890=80235；
             水的沸点是 100°C（标准大气压）。
未完成：用户询问日语「再见」的说法。
```

`/context` 会多出这几行：

```
上下文 约 409 / 500 tokens（82%） · 共 10 条消息 · 摘要 161 tokens
长期记忆      摘要 161 tokens（占上下文 39%）
压缩记录      1 次成功
压缩开销      输入 608 / 输出 181 tokens（累计压掉原文约 310 tokens）
结构自检      健康
```

**💡 所以呢**

三个观察：

1. **摘要是有结构的**，不是一段散文。因为压缩指令里写死了
   「目标 / 关键信息 / 已确认的事实 / 未完成」四类 ——
   详见 `compaction.py` 里的 `COMPACTION_INSTRUCTION`。
2. **它是「有损」的**。你原来还说过「只回复好的两个字，不要调用工具」这个约束 ——
   摘要里还有吗？**去看看。** 如果没了，说明这类细节确实会被丢掉。
3. **信息密度很高**：161 tokens 装下了 5 轮对话。

> 💡 把你的摘要贴到实验记录表里。**这份摘要就是你 Agent 的「记忆分辨率」。**

# 第二组 · 亲手把它拆掉

> **要证明一个能力真的在起作用，最好的办法是把它拿掉。**
>
> 这一组的四个实验，都是让你「破坏」点什么 —— 然后看它怎么坏。

## 实验 3：关掉压缩 ⭐⭐

**🎯 要感受什么**

**同一个 Agent、同一段对话、同一个模型**，只关掉压缩 —— 它立刻变回 v2。

**⌨️ 敲什么**

```bash
LLM_MAX_CONTEXT_TOKENS=500 LLM_KEEP_RECENT=4 LLM_SUMMARY_ENABLED=0 python main.py
```

启动时横幅会红字写着：

```
记忆压缩 已关闭 —— 退回 v2 的「丢弃」行为
```

然后**把实验 1 那 9 句话一字不差地再输一遍**。

**👀 看什么**

| | 压缩开（实验 1） | 压缩关（本实验） |
|---|---|---|
| 中途 | `🗜 第 1 次压缩：5 轮旧对话 → 摘要 161 tokens` | `✂ 丢弃 4 轮旧对话（内容不再保留）` |
| 紧跟的行 | （没有） | `⏭ 没有走压缩：记忆压缩被关闭了（LLM_SUMMARY_ENABLED=0）` |
| 最后问暗号 | **「紫色河马」** ✅ | **「你并没有让我记过任何暗号」** ❌ |

而且注意第二列的回答 —— 它不只是不知道，它还会**编一段解释**：
「你先后问了水的沸点、让我算了几道题，从没提过暗号」。
**语气一模一样地自信。**

**💡 所以呢**

这一组对照说明了两件事：

1. **能力确实来自压缩**，不是运气、不是模型变强了
2. **失忆是不报错的**。你看到的「它答不出来」是好事，真实系统里更常见的是
   —— 它**编一个像模像样的答案**，而你以为它记得

## 实验 4：把摘要模板改坏 ⭐⭐

**🎯 要感受什么**

压缩的质量**全部押在那段提示词上**。改一句，保真度就崩。

这正好呼应 v1 实验 10 的结论：**提示词就是程序**。

**⌨️ 敲什么**

**第一步**：打开 `compaction.py`，找到 `COMPACTION_INSTRUCTION`，
把整个输出格式那段（`严格按下面的格式输出…` 那四行）删掉，
换成一句：

```python
严格输出一段不超过 100 字的纯文本概括，不要分点，不要小标题。
```

**第二步**：用实验 1 的命令和对话重跑一遍：

```bash
LLM_MAX_CONTEXT_TOKENS=500 LLM_KEEP_RECENT=4 python main.py
```

**第三步**：压缩发生后，敲 `/summary` 看摘要，再问暗号。

**👀 看什么**

- 摘要变成**一段流畅的散文** —— 读起来很顺，很像回事
- 但「暗号是紫色河马」很可能**没了**，或者变成了「用户提到了一些需要记住的信息」
- 最后问暗号 —— 大概率答不出来

**💡 所以呢**

对照一下两种模板的差别：

| 原模板里的一句话 | 为什么必须有 |
|---|---|
| 「**必须**保留：代号、暗号、名称、数字…」 | 不点名要什么，模型就按「什么读起来顺」来删 |
| 「一条都不能漏」 | 不给强度，它就真的会漏 |
| 「只写真实出现过的信息，不要推测」 | 不写这句，它会在复述时**顺手脑补** |
| 四个固定小标题 | 结构化输出比自由散文的信息密度高得多 |

> **压缩是唯一一个「模型写错字，你就永久失忆」的地方。**
> 其他地方的提示词写坏了顶多是答得不好；这里的提示词写坏了，
> 被压掉的内容**再也没有第二次机会**。

**一键复原**：

```bash
cd <仓库根> && git diff agent-v3/compaction.py   # 看改了什么
git checkout agent-v3/compaction.py              # 恢复原样
```

## 实验 5：让压缩失败 ⭐

**🎯 要感受什么**

v3 里最不起眼、但最值钱的一段代码：**压缩失败之后会怎样。**

**⌨️ 敲什么**

给压缩单独喂一个不存在的模型名：

```bash
LLM_MAX_CONTEXT_TOKENS=500 LLM_KEEP_RECENT=4 LLM_SUMMARY_MODEL=no-such-model python main.py
```

然后照旧聊到触发点。

**👀 看什么**

三件事，一件都不能少：

1. **对话本身完全正常** —— 前面的计算、问答一个不落
2. 该压缩的时候，出现的是：

```
⚠ 压缩失败：NotFoundError: ...（已回退到「丢弃」）
```

3. **对话没有中断，也没有报错退出** —— 它只是悄悄退回了 v2 的行为

**💡 所以呢**

去看 `context.py` 里 `_compact_or_drop()` 的这个分支：

```python
except Exception as exc:
    # 压缩失败不能连累整次请求 —— 这是工程底线。
    report.compaction_error = f"{type(exc).__name__}: {exc}"
    self.compaction_failures += 1
    report.dropped_rounds += self._drop_oldest_rounds()
    return
```

**只有 5 行，但它决定了这个 Agent 能不能上生产。**

想一想：如果没有它，网络抖一下 = 用户的对话直接挂掉。
而你花了那么多功夫做的压缩，会在最不该出问题的时候，变成单点故障。

> **降级路径比主路径更重要。** 主路径决定你有多好，降级路径决定你能不能用。

## 实验 6：把阈值调到天上去 ⭐⭐

**🎯 要感受什么**

v3 里藏着一个开关，能让它**悄无声息地退回 v2**，而横幅上还写着「压缩：开」。

**⌨️ 敲什么**

```bash
LLM_MAX_CONTEXT_TOKENS=500 LLM_KEEP_RECENT=4 LLM_MIN_COMPACT_TOKENS=100000 python main.py
```

（意思：不到 10 万 token 的可压内容就别压了 —— 永远达不到）

**👀 看什么**

- 横幅显示：`记忆压缩 开` ✅
- 但终端里出现的全是 `✂ 丢弃 N 轮旧对话` ——**一次 `🗜` 都没有**
- 而且紧跟每一句「丢弃」的，是它自己招供的原因：

```
⏭ 没有走压缩：可压内容只有 175 tokens，低于阈值 100000（调小 LLM_MIN_COMPACT_TOKENS 就会压）
```

- 问暗号：答不上来

**💡 所以呢**

这就是 `_compact_or_drop()` 里那条「岔路 2」：

```python
if self.summarizer is None or chunk_tokens < self.min_tokens_to_compact:
    report.dropped_rounds += self._drop_oldest_rounds()
    return
```

**这个判断本身是对的**（内容太短时压缩是亏本的，见实验 7），
但它揭示了一个只有跑起来才会发现的道理：

> **一个功能的开关状态，不等于它真的会被用到。**

配置显示「开」、代码里也没有 bug —— 但行为上它和 v2 一模一样。
真实系统里这种「看起来开了、其实没生效」的状态最难查，
因为这个实验的存在，你以后会知道去哪找：
**不是看配置，是看日志里到底出现了哪个 emoji。**

> 顺便说：默认值 200 就是从这个坑里调出来的 ——
> 最初写的是 400，结果预算 400 以下时压缩**永不触发**，
> v3 在那些配置下等于没做。

---

**再附一个细节：那个 `⏭` 行，是被人问出来的。**

最初的日志只有一句「✂ 丢弃 1 轮旧对话」。信息是对的，但**不够用** ——
看的人分不清它到底是压缩坏了、压缩被关了、还是压根没打算压。

于是有了这条设计规则，它已经写进 [AGENTS.md](../AGENTS.md) 的**铁律 7**：

> **每一条「我没做 X」，都要说清楚「因为 Y」。**
>
> 日志不是写给自己看的备忘，是给「看不懂的人」看的证据 ——
> 而那个人往往就是三天后的你自己。

# 第三组 · 感受代价

> 前面两组证明了压缩有用。这一组要告诉你：**它不便宜，也不完美。**

## 实验 7：压缩的账 ⭐⭐⭐

**🎯 要感受什么**

**压缩不是省钱的。** 它的价值在别的地方 —— 这一条如果你不亲手算过，是不会信的。

**⌨️ 敲什么**

用实验 1 的配置跑一段**较长的**对话（15 轮以上），每次都把这几行抄下来：

```
🗜 第 N 次压缩：M 轮旧对话（K 条消息） → 摘要 X tokens，压缩比 P%
   上下文 C → D tokens
   压缩调用：A 输入 / B 输出 tokens · 耗时 T s
```

跑完之后算三个数：

| 算什么 | 怎么算 |
|---|---|
| **这次压缩花了多少** | `A + B`（压缩调用真实花掉的输入 + 输出） |
| **这次压缩省了多少** | `摘要 tokens ÷ 压缩比 − 摘要 tokens`（报告里的两个数就能算） |
| **总账** | 所有压缩的（花掉 − 省下）加起来 |

**👀 看什么**

这是**实测跑出来的真实数字**（不是估算）：

```
🗜 第 1 次压缩：5 轮旧对话（14 条消息） → 摘要 161 tokens，压缩比 52%
   上下文 501 → 409 tokens
   压缩调用：608 输入 / 181 输出 tokens · 耗时 1.2s
```

| | 数字 |
|---|---|
| 花掉 | 608 + 181 = **789 tokens** |
| 省下 | 约 **150 tokens** |
| **净结果** | **倒亏 639 tokens** |

**💡 所以呢**

**单看这一次，压缩是亏的，而且是巨亏。**

那为什么还要压？因为两者省的**根本不是同一种东西**：

| | 省的是什么 | 何时兑现 | 信息 |
|---|---|---|---|
| 丢弃 | token | 只兑现一次 | **永久消失** |
| 压缩 | token | **每一轮请求都在省** | 留在摘要里 |

所以正确说法不是「压缩省钱」，而是：

> **压缩是拿一笔一次性、可接受的开销，去买「长期的信息存续」。**

真要靠压缩省钱，得**压大块内容**：压 5 轮的固定开销（指令约 250 tokens）
都摊不平；但压 50 轮时，这 250 tokens 就是九牛一毛了。
这正是 `LLM_MIN_COMPACT_TOKENS` 存在的理由。

> 顺便想想：如果把 `LLM_MIN_COMPACT_TOKENS` 从 200 调到 1000，
> 这个 Agent 会变成什么样？（会更省钱，还是更容易忘事？）

## 实验 8：压了又压 ⭐⭐⭐

**🎯 要感受什么**

**每次压缩都是一次有损转换。** 压了三次之后，第一次的内容还剩多少？

这是整份手册里最诚实的一个实验 —— 它会告诉你记忆的真实保质期。

**⌨️ 敲什么**

```bash
LLM_MAX_CONTEXT_TOKENS=600 LLM_KEEP_RECENT=4 python main.py
```

**第一步**：埋三个暗号，中间隔着多轮无关对话：

```
请记住第一个暗号：紫色河马。只回复「好的」。
（…聊 5 轮无关的…）
请记住第二个暗号：绿色骆驼。只回复「好的」。
（…再聊 5 轮…）
请记住第三个暗号：蓝色鲸鱼。只回复「好的」。
（…再聊 5 轮…）
```

**第二步**：每次看到 `🗜` 就敲一次 `/summary`，把摘要抄下来。

**第三步**：最后问：

```
我让你记过哪几个暗号？按顺序说。
```

**👀 看什么**

把每次的摘要按时间排开，你会看到一条**漂移轨迹**：

| 第几次压缩 | 摘要里还剩什么 |
|---|---|
| 1 | 「紫色河马」原样在 |
| 2 | 「紫色河马」还在，但可能变了措辞 |
| 3 | 紫色河马？措辞继续漂移，细节（比如「只回复好的」）早就没了 |

预期结果：**最近的暗号一定记得，最早的暗号开始变形或消失。**

**💡 所以呢**

三件事，一件比一件重要：

1. **信息不是「在」或「不在」，而是在流失。** 第一次压缩后它是原文，
   第二次后它是转述，第三次后它是**转述的转述**。
2. **这就是为什么 `--selftest` 的 D3 盯着「压两次、两个暗号都要在」** ——
   那是这个能力能不能成立的下限。
3. **工程上的启示**：真正不能丢的东西，不能只靠上下文里的摘要。
   它需要一条**独立的、不会被反复改写的**通道 ——
   写进文件（`save_note`）、或者下一版的**持久化记忆**。

> 试着数一数：**这个 Agent 的记忆，大概几轮之后开始不可靠？**
> 这个数字比任何文档都诚实。

## 实验 9：摘要的「分辨率」⭐

**🎯 要感受什么**

摘要长度不是「越长越好」——它是一根两头扎手的旋钮。

**⌨️ 敲什么**

准备两段相同的对话，分别用不同的摘要上限跑：

```bash
LLM_SUMMARY_MAX_TOKENS=60    LLM_MAX_CONTEXT_TOKENS=500 LLM_KEEP_RECENT=4 python main.py
LLM_SUMMARY_MAX_TOKENS=2000  LLM_MAX_CONTEXT_TOKENS=500 LLM_KEEP_RECENT=4 python main.py
```

每次都等到 `🗜`，然后 `/summary` + 问暗号。

**👀 看什么**

| | 摘要 60 tokens | 摘要 2000 tokens |
|---|---|---|
| `/summary` 里有什么 | 一两句话，只够装下最粗的结论 | 四类信息齐全，细节丰富 |
| 暗号还在吗 | 可能没了（被挤掉了） | 大概率在 |
| `/context` 显示的「摘要 X tokens」 | 很小 | 很大 |
| 压缩完之后上下文 | 一下就掉下来了 | 没掉多少，**可能马上又要压** |

**💡 所以呢**

这就是一根真实的权衡曲线：

| | 保真度高 | 省 token |
|---|---|---|
| 摘要长 | ✅ | ❌ |
| 摘要短 | ❌ | ✅ |

而且短摘要有个**隐藏代价**：摘要太短 → 省下的 token 多 → 久一点才会再超预算。
但短摘要丢的信息，**没有任何地方能找回来**。

**没有正确答案，只有你的场景需要什么**：

- 客服机器人？用户刚才说的最重要 → 摘要可以短
- 长文档分析？开头的约束必须在 → 摘要得给足

> 回到那句老话：**一个数字就能改变 Agent 的「人格」。**
> v2 里那个数字是预算，v3 里多了三个：摘要上限、压缩阈值、用哪个模型压缩。
