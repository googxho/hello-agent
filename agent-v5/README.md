> 第五个版本。前面四版让它**记住你说过的话**，这一版让它**去翻你的资料**。

v4 结束时，它对「你告诉过它的事」记得很牢 —— 可对你**已经写在磁盘上的东西**，
一无所知。

## 每一版都回答四个问题

### ① 上一版遇到了什么具体问题？

v4 把「重启就忘」解决了，但它记住的仍然只是**你说给它听过的话**。

你写在磁盘上的东西 —— 笔记、文档 —— 它一无所知。
**更准确地说：它连「你有笔记」这件事都不知道。**

**实测对照**（同一份笔记 `chenxi.md`，就放在 `notes/` 目录里）：

| | v4 | v5 |
|---|---|---|
| 问「我的笔记里，晨曦项目什么时候交付？负责人是谁？」 | 「我**没有读取或检索已有笔记的能力**——所以我无法看到……」❌ | 「根据你的笔记（chenxi.md）：**交付时间**：本周五交付第一版；**负责人**：老王」✅ |

> 注意 v4 那句话 —— 它说得很诚实，甚至有点委屈：
> **「我没有…能力」**。问题不在它的态度，在于**没人给它一把钥匙**。

### ② 这一版引入什么最小概念？

> **资料太多，塞不进上下文 —— 那就先找出来，再塞进去。**

```
问题 ──→ 检索器 ──→ 最相关的 N 段 ──→ 塞进上下文 ──→ 模型回答
```

一条流水线。真正花心思的是里面**三个必须做的决定**（下一节展开）：

| 决定 | 这一版的选择 | 为什么 |
|---|---|---|
| **怎么切** | 按 Markdown 标题 + 段落切 | 段落是语义的自然边界，不会把一句话劈成两半 |
| **怎么找** | 关键词打分（IDF × 饱和词频） | 零依赖、零 API 调用、**完全离线可测** |
| **中文怎么办** | 字符 bigram（「性能优化」→ 性能/能优/优化） | 中文没有空格，而装分词器要引入新依赖 |

> ⚠️ **为什么不直接用 embedding？** 因为那样就需要一个 embedding 服务
> （要申请 Key、要联网、要花钱），**自检就没法离线跑了**。
>
> 这一版先把**流水线**跑通 —— 换掉其中一个环节（打分算法）就能升级成语义检索，
> 那是下一版的事。**先跑通，再跑好。**

### ③ 如何验证它真的解决了？

两层，都做过：

1. **离线断言**：`--selftest` 共 **89 项**，其中 20 项专门测检索
   （切分、分词、IDF、排序、出处、索引重建、坏文件、空目录）—— 不花钱，不碰你的笔记
2. **真实对照**：上面那张 v4 vs v5 的表，就是跑出来的

### ④ 下一版的新痛点是什么？

**关键词检索靠的是「字面相同」。** 所以：

```
笔记里写「性能优化」  →  你问「怎么让它更快」  →  检索不到 ✗
```

同义词、近义表达、跨语言的语义相似 —— 这一版**全部无能为力**。
这不是 bug，是这类方法的**天花板**。

| 更细的坑 | 说明 |
|---|---|
| **召回太多会挤爆上下文** | 带 20 段回来，一半是噪音 —— 又撞上 v2 的预算问题 |
| **切分粒度是双刃剑** | 切太碎 → 前后文丢了；切太大 → 一块里混着好几件事，检索不准 |
| **它得先知道该查** | 模型不会自动检索 —— 要靠工具描述引导（v1 的老话题） |
| **没有重排** | 这一版按分数排序；社区还会用第二个模型重新排一遍（rerank）|

**→ v6 方向**：把「关键词打分」换成 **embedding（向量检索）**，
让它能按**意思**找，而不是按**字**找。

## 快速开始

沿用你机器上的 `myenv` 虚拟环境（依赖和 v1~v4 完全相同，**零新增依赖**）。

```bash
myenv
cd agent-v5

# 先跑自检 —— 不需要 API Key，不花钱，也不会碰你的笔记和会话文件
python main.py --selftest

# 开始对话
python main.py
```

**不需要复制 `.env`。** 配置分两层，各归各位：

| 层 | 文件 | 放什么 | 谁在用 |
|---|---|---|---|
| **共享层** | `<仓库根>/.env` | 密钥、接口地址、模型名 | 所有版本 |
| **版本层** | `agent-v5/.env` | v5 独有的调参 | 可选，不存在也没关系 |

v5 新增这四项，模板见 `agent-v5/.env.example`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `LLM_NOTES_DIR` | `agent-v5/notes` | **资料目录** —— 它要读的「图书馆」在哪 |
| `LLM_RETRIEVAL_ENABLED` | 1 | 检索开关（0 = 退回 v4）|
| `LLM_RETRIEVAL_TOP_K` | 5 | 每次带回来几段 |
| `LLM_CHUNK_MAX_CHARS` | 600 | 一块最大多少字符（切分粒度）|

**想让它读你自己的文档？** 指过去就行：

```bash
LLM_NOTES_DIR=~/我的文档 python main.py
```

## 核心概念：三个决定

### 决定一：怎么切（chunking）

文件不能整篇塞进去（太长），也不能按固定字数硬切（会把一句话劈成两半）。

这一版按**结构**切：先认 Markdown 的标题，再按空行切段落。

```
一篇笔记
  ├─ # 晨曦项目      → 段落 1
  ├─ ## 交付物       → 段落 2
  └─ ## 风险         → 段落 3
```

**每块都记住三件事**：来自哪个文件、哪一行、属于哪个小节。

这不是装饰 —— 它是「结果能被回溯」的保证：你看到的不只是答案，
还有「它是从哪个文件哪一行找出来的」，可以自己去核对。

### 决定二：怎么找（打分）

朴素做法是「查到了就得分」，它有两个毛病：

- 常见词（「的」「是」「项目」）到处都是，命中它们毫无信息量
- 一段文字里出现 10 次 ≠ 比出现 1 次相关 10 倍（收益该饱和）

所以用 **IDF + 饱和词频**（BM25 的核心思想）：

```
score(查询, 文段) = Σ    idf(词) × tf / (tf + 1.5)
                  词∈查询

idf(词) = log(1 + (总块数 − 含该词的块数 + 0.5) / (含该词的块数 + 0.5))
```

翻译成人话：

- **越罕见的词越值钱**（idf 大）
- **同一个词重复出现，收益递减**（tf/(tf+1.5) 会趋近于 1）
- **标题里命中的词，权重加一倍**（标题是作者划的重点）

### 决定三：中文怎么办（分词）

英文有空格，`split()` 就完事。中文没有 —— 而装一个分词器（jieba 之类）
就要引入新依赖。

所以这里用**字符 bigram**：把连续的中文切成两字一组。

```
「性能优化」 →  性能 / 能优 / 优化
```

土，但有效：只要查询里的词在文段里出现过，就至少有一个 bigram 命中。

> **代价是什么？**「能优」这种没意义的组合也进了索引 ——
> 这是它的副作用，也是为什么它**仍然解决不了同义词问题**（见实验 3）。

## 它会翻你的资料了 —— 但你看得见吗？

### 检索发生时，终端会说话

```
你 > 我的笔记里，晨曦项目什么时候交付？
  🔍 检索 晨曦项目 交付 → 3 段命中（最高分 2.41 / 1.29 / 0.35 · 扫描 6 块 · 0.8 ms）
      chenxi.md:3（chenxi） · 命中 晨曦、曦项、项目、交付
      chenxi.md:7（交付物） · 命中 交付、付物
```

**每一段都告诉你**：从哪个文件哪一行来、命中了哪些词、得分多少。

没有这些，检索就是个黑盒 —— 你没法判断它「找对了」还是「蒙对了」。

### 空手而归时，它会提醒你盯住模型

```
  🔍 检索 网球拍穿线磅数 → 0 段命中（扫描 6 块 · 0.4 ms）
      ⚠ 资料里没有相关内容 —— 它接下来应该说「不知道」，而不是编一个〔盯一下〕
```

这一行是刻意加的：**检索落空时，是幻觉最容易发生的时刻。**

### `/knowledge` —— 看看它的「图书馆」

```
资料目录  /Users/kuki/homework/hello-agent/agent-v5/notes · 2 个文件 / 6 块
          · 索引重建过 1 次
```

索引是**懒加载**的（第一次检索时才建，启动不会变慢），
而且你新写的笔记**下一次检索就能看到** —— 靠比较目录的「指纹」自动重建。

## 文件结构

```
agent-v5/
├── main.py         CLI 入口：/knowledge 命令、--selftest（89 项）
├── retrieval.py    ⭐⭐ 本版核心：切分 + 分词 + 索引 + 打分
├── tools.py        ⭐ 加了第 4 个工具 search_notes（v2 以来第一次改动）
├── context.py      上下文管理（v4，零改动）
├── storage.py      会话存取（v4，零改动）
├── compaction.py   上下文压缩（v3，零改动）
├── agent.py        Agent 主循环（v4，零改动）
├── llm.py          LLM 调用封装（v3，零改动）
├── config.py       配置：新增检索四项
└── .env.example    版本层模板
```

**为什么 `search_notes` 放在 `tools.py` 而不是 `retrieval.py`？**

因为它们是两件事：

- `retrieval.py` 回答「**怎么找**」（切、分词、打分）—— 纯逻辑，可以单独测
- `tools.py` 回答「**怎么介绍给模型**」（工具名、描述、参数）—— 协议层

分开了，你才能把检索器单独拎出来测（`--selftest` 就是这么做的），
以后换掉打分算法（比如换成 embedding）也不用动工具协议。

| ④ 压缩 | 33 | v3 的核心（D1~D7）|
| ⑤ 持久化 | 24 | v4 的核心（E1~E4）|
| **⑥ 本地检索** | **20** | **v5 的核心（F1~F8）** |

第 ⑥ 组的八个场景：

| 场景 | 关键断言 |
|---|---|
| **F1** 切分 | 三小节的笔记切成 3 块、标题/文件/行号都记得 |
| **F2** 分词 | bigram 正确、英文小写化、停用词被丢 |
| **F3** IDF | 罕见词权重 > 常见词 |
| **F4** 检索 | ⭐ **问对的问题，排第一的是对的那块**（而且没串到别的文件）|
| **F5** 落空 | 问资料里没有的东西 → 0 命中，不硬凑 |
| **F6** 索引重建 | 新写的文件马上能检索到 |
| **F7** 坏文件 | 读不了的文件被跳过，检索不崩 |
| **F8** 目录不存在 | 返回空，而不是崩 |

> **全部在系统临时目录里跑** —— 不碰你真实的 `notes/` 和 `session.json`。

## 常见问题

**Q：它每次都检索吗？**
不是 —— 由**模型自己决定**。工具描述里写的是「当用户问起『我记过什么』，
或者问题可能涉及用户的个人资料时，必须先调用本工具检索」。
你可以试试问它「1+1 等于几」，看它理不理你的笔记。

**Q：我的笔记在 `agent-v4/notes/`，v5 看得到吗？**
看不到 —— 每个版本有自己的 `notes/`。想看 v4 的，指过去：

```bash
LLM_NOTES_DIR=../agent-v4/notes python main.py
```

**Q：我新写的笔记，它什么时候能看到？**
下一次检索时（它会比较目录指纹，变了就重建索引）。
不用重启程序。

**Q：能读 PDF / Word 吗？**
不能，现在只认 `.md` / `.txt` / `.markdown`。
加格式解析器是「加工具」的活 —— 但先想想：**你真的需要吗？**

**Q：检索结果里有些明显不相关的段，怎么办？**
调小 `LLM_RETRIEVAL_TOP_K`（默认 5），或者调大 `LLM_CHUNK_MAX_CHARS`。
更好的办法是**换个说法再问** —— 这一版认字面，实验 3 会告诉你为什么。

## 动手练习

1. **读一遍 `retrieval.py` 的 `tokenize()`** —— 试试给一段中英混合的文字手动推演一遍它会被切成什么
2. **让它读你的真实文档** —— `LLM_NOTES_DIR=~/某个文件夹 python main.py`，看看它在你的资料上表现如何
3. **加一个 `list_notes` 工具** —— 让它能「列出有哪些笔记」（这是 v2 实验 6 里欠下的练习）
4. **给检索结果加个上限** —— 如果召回的内容太长，把它们截断再塞进上下文（你会用上 v2 的 `MAX_TOOL_RESULT_CHARS`）
5. **思考题**：把 `search_notes` 的 `limit` 参数去掉，会发生什么？
   （提示：模型可能不会传这个参数 —— 这是 v1 实验 10 的老话题）

## v4 到哪里去了？

没删。`agent-v4/` 原样保留，它是**最好的对照组**：

```bash
diff -u ../agent-v4/main.py main.py        # 看 /knowledge 与横幅改了什么
```

你会发现 `agent.py` / `context.py` / `storage.py` / `compaction.py` **一行都没动** ——
加一个「查资料」的能力，不需要碰记忆、压缩、持久化任何一层。
